A source-backed mental model

From a tap to durable household truth.

The browser presents and reacts, Next.js composes and coordinates, and Postgres commits the truth. Pure TypeScript rules make the behavior understandable and testable, while database functions enforce the invariants that must survive retries and two people acting at once.

This walkthrough is based on the current worktree at commit 4bf8e4b. It describes implemented code, and it calls out boundaries that are architectural intent rather than pretending every planned service is complete.

          Business boundaries

          Each domain owns one kind of truth.

          The domains collaborate through explicit handoffs. Meals can create grocery intent, shopping can create an expense draft, and only Money can turn that draft into ledger history.

          The most important wall is between household work and financial obligations. Completing a chore never changes who owes whom.

                Security and consistency

                Assume every mutation is a public API call.

                A hidden button is not authorization. The server establishes the member context, RLS scopes every tenant row, and sensitive database functions validate the caller again inside the transaction.

                The browser receives a publishable key and a member session. The Supabase administrator secret stays in local enrollment commands, while Edge-only service credentials live in Edge secrets.

                Three checks protect one mutation.

                Each boundary assumes the previous one can be bypassed. That duplication is deliberate because a direct network call can skip the UI and race conditions can invalidate an earlier read.

                Boundary 1

                Identity

                Supabase Auth proves which user controls the session through a passkey. It does not grant household access by itself.

                Boundary 2

                Membership

                requireMemberContext() maps the authenticated user to one household and redirects authenticated outsiders to Access Denied.

                Boundary 3

                Database authority

                RLS and transactional RPCs recheck membership, validate invariants, acquire locks where needed, and reject unsafe state transitions.

                  Orientation guide

                  Know where to look before reading everything.

                  Start at the route for the screen, follow its read model or server action into src/lib, then open the RPC definition in the matching migration when durable state changes.

                  The repository is one root Next.js app on purpose. Folder boundaries create separation without package manifests, cross-package builds, or a second deployment.

                  The safety net has three distinct jobs.

                  Fast TypeScript tests explain rules, pgTAP attacks database guarantees, and Playwright proves selected user journeys across the browser/server boundary.
