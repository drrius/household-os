# Default grocery edit versions

Default groceries previously accepted edits by identity alone, so a partner could overwrite a newer quantity, category or note. Each template now has an authoritative timestamp advanced on every update, including archive/restore, and an edit requires the exact opened version. The trigger advances monotonically even within one transaction. Application members cannot update that column directly. A stale or unavailable row returns a reload message. New-item collision retries also require the existing item to remain active.

The editor pairs the version with the visible fields and category options. Pristine rows receive partner updates; dirty fields, category-only changes and rejected submissions keep the original baseline; reverting adopts the waiting refresh. New creation IDs retain their established retry lifetime. Existing real server-redirect regressions cover successful repeated saves and creation.
