# Plans, confirmations and paid expenses

Trip/project details and each booking now show a paid-cost summary, links to record a paid expense or associate an existing one, and a paginated document section with current/archive navigation. Booking actions carry the booking identity into Money. The displayed total comes from the existing authoritative cost-context RPC and includes refunds/corrections; no new financial arithmetic, ledger write rule or schema migration is introduced. Inventory and commitments use the same summary/actions. Money's cost page links back to its associated plan, booking or household record.

Adding a document from a plan or booking prefills authorized parent choices. The document schema now preserves `booking_id`, which the existing database already supports and constrains to its own trip. Selectors show only bookings belonging to the selected project, and changing the parent clears incompatible relationships. Save/edit preserves the link and detail pages link back to the booking. Return paths retain the parent page context and reject outside URLs and action routes. Shared record forms enable the existing unsaved-change guard.

Archive state hides new expense/document actions while preserving inspectable costs and documents. A booking also links directly to its calendar event. A pending or estimated booking never counts as a payment.

Evidence: 54 focused record/validation/cost-context tests pass, including property coverage that booking-linked documents require a project, authorized prefill choices, forbidden return destinations, and persistence across create/edit. Six browser cases pass across Chromium and mobile Safari: the existing private-document flow, booking-scoped expense/document links, archived read access, confirmation save/edit, filtering another trip's bookings and declining accidental navigation. Targeted lint and typechecking pass. SQL011 adds five database assertions for booking/document tenancy and composite-parent identity; these require hosted CI.
